# Start a Mentored Frontend Assignment

Hubert shapes frontend work and specifies the backend calls. The
[assignment catalog](work-units/README.md) gives contributors five small research and
design assignments with manifests, AI prompts, deliverables, and review checkpoints.

## Select one assignment

Start with the contributor's interests, available session, and desired skill.
Offer research, specification, wireframing, visual design, or API-contract work when
its prerequisites are satisfied. Keep one assignment active per contributor.

The [team norms](https://docs.google.com/document/d/1v_cuc_hEcx9GzcsoE8GJv83o_qlVc3QX-LhdtlUGqHA/edit)
describe a shortage of scoped tickets and limited review capacity. A bounded
deliverable makes the next contribution and review concrete. Artifact volume is not
the success measure.

Use a 15-minute opening checkpoint:

1. Ask the contributor to explain the outcome in their own words.
2. Check issue comments, existing artifacts, and current claims.
3. Confirm the inputs, timebox, deliverable, and available reviewer.
4. Run the manifest's brainstorming prompt together.
5. Ask the contributor to choose and explain the next step.

## Teach judgment through AI use

Use the manifest's prompts in order: explore, produce, and challenge as specified.
The contributor checks citations, compares alternatives, and inspects the artifact.
Ask them to identify one suggestion that lacked evidence or violated the brief.

For a wireframe, have the contributor trace the resident's actions. For a specification,
trace action, state, visible result, and data need. For a backend call, separate the
proposed contract from capabilities demonstrated by the code.

At review, ask for a five-minute demonstration and one remaining uncertainty.
Product/design approve their interpretation and visual choices. Hubert accepts the
frontend handoff. The backend lead confirms the shared call contract.

## Keep work easy to resume

Record a short checkpoint in the issue:

```text
Assignment and contributor:
Accepted input revision:
Artifact link and revision:
Evidence checked:
Decision or blocker:
Next action and next check-in:
```

Keep product research and design originals in Drive or the approved Figma file.
Keep engineering decisions in GitHub. Summarize coordination in a Slack thread when
needed. A maintainer handles stale claims using the team's two-week convention.

Review the pilot after three completed assignments. Check time to first artifact,
review effort, acceptance clarity, and contributor confidence. Record one confusing
step and one useful lesson per assignment.
